# Studio · 英语阅读训练桌面应用

一个只做一件事的工具：**每天读一篇你真正感兴趣、长度你自己定的英文文章，先听，再读，猜一遍词，最后用一次。**

文章由 AI 现写，题由 AI 现出，数据全部存在你自己电脑上。

---

## 它解决的是什么问题

不是「词汇量不够」，而是**词认识、但调不出来、听不出来**。

所以这个工具里没有背单词列表，只有一条链：

```
听（原文遮住）→ 读（点词发音）→ 猜词（三个勾算掌握）→ 翻译 + 造句
```

这条链的每一个环节都可以在「设置 → 学习环节」里开关；听力不行可以选「先读后听」，先看懂原文再放朗读磨耳朵。

词汇的熟练度不是数「背过几遍」，而是**在语境里第几次认出它**。每猜对一个词，那个词拿一个勾；三个勾，才算「初步掌握」。

---

## 功能

**文章**
- 长度可选：短 150 / 中 250 / 长 400 词，AI 按硬约束写，界面显示真实词数
- 兴趣方向可自己填，写完自动出听力题、阅读题、长难句翻译、搭配造句
- 随时重写，历史文章都在「文库」

**流程**
- 听力 / 猜词 / 综合训练三个环节可独立开关，关掉的不进流程
- 听力顺序可选：先听后读（默认）或先读后听

**听**
- 逐句合成、逐句定位：点哪句从哪句播，单句可循环
- 六个音色（美音 Aria / Jenny / Guy / Andrew，英音 Sonia / Ryan），语速四档
- 第一次听力时原文完全遮住，只听
- 阅读页也能听：全文朗读，或点每段左边的小三角只读那段

**猜词**
- 读完原文后，逐个词猜中文意思，四选一
- 猜对给一个勾，猜错不给，并且当场告诉你正确答案
- 三个勾 = 初步掌握；每个词的状态在词书里一眼可见

**词书**
- 内置 **7,777 个六级词汇**（来自用户提供的《六级词汇7884词》词表，含音标）
- 按「未开始 / 学习中 / 已掌握」筛选，可搜索，120 个一页
- 两页：六级词汇 / 我遇到过的词
- 支持导入自己的词表（TXT / CSV，每行 `word,pos,释义`）
- AI 选词会自动优先「还没拿满三个勾」的词

**成长**
- XP + 等级（120 XP 一级）
- 16 个成就
- 14 天阅读词数折线
- 只记录真实发生的事：**没有连续打卡，没有断签惩罚**

## 启动

### 方式一：源码运行

```bash
npm install
npm start
```

或者双击 `启动 Studio.bat`。

### 方式二：打包成独立 exe

```bash
npm run pack
```

产物在 `release/`。`release/` 不进仓库（体积大），本地构建一次即可。

## 第一次使用：填一个免费 Key

文章是 AI 写的，所以要一个 API Key。推荐**智谱 GLM-4-Flash**：永久免费、国内直连、不用绑卡。

1. 打开 https://open.bigmodel.cn
2. 手机号注册
3. 「API Keys」→ 新建 → 复制
4. 打开 Studio → 左下角「设置」→ 粘贴 → 点「测试连接」

Key 只存在本机 `%APPDATA%\cet6-studio\data.json`，不会上传，也不会进这个仓库。

设置里另外备了三个可切换的服务商：硅基流动、火山方舟（豆包）、任何 OpenAI 兼容接口。

## 为什么是桌面应用

两个原因，都是网页做不到的：

1. **语音**。系统自带的 SpeechSynthesis 在 Windows 上经常只有中文语音，用它读英文等于报废。这里走微软 Edge 的在线 Neural 语音（`msedge-tts`），免费、不需要 Key、音质接近真人——但它需要 Node 侧的合成能力。
2. **跨域**。AI 请求走主进程的 Node `fetch`，不受浏览器 CORS 限制。

## 技术结构

```
main.js        主进程：窗口、JSON 文件存储、AI 请求、Edge TTS 合成（含缓存）
preload.js     只暴露 4 个 IPC，contextIsolation 开启
index.html     全部页面（10 个 section，切换显示）
app.js         全部逻辑：推荐、选词、播放器、猜词、词书、成就
words.js       内置六级词表（402 词）
styles.css     样式
build/         图标（SVG 源 + 生成的 ico/png）
tools/         make-icon.js：SVG → 多尺寸 PNG → ico
```

- 无框架、无构建步骤，Electron + 原生 JS
- 数据存 `%APPDATA%\cet6-studio\data.json`（单文件，可备份、可手改）
- 语音逐句合成 + 内存缓存 + 串行预取后面几句

### 几个踩过的坑（写在这里省得再踩）

- **CSP 必须包含 `media-src 'self' blob: data:`**，否则 blob 音频报 `MEDIA_ERR_SRC_NOT_SUPPORTED`。
- **`ELECTRON_RUN_AS_NODE=1` 会让 electron.exe 当普通 node 跑**，启动脚本里要清掉。
- **打包后 userData 目录会变成 productName**，所以主进程里用 `app.setPath('userData', …)` 固定成 `cet6-studio`。
- **小模型控不住总词数**。GLM-4-Flash 对「总词数 220–280」几乎无感（实测输出 74–142 词）。改成约束「4 段 × 每段 3–4 句 × 每句 18–25 词」才有效，另加一次自动扩写兜底。
- **`glm-4.7-flash` 不能用作默认**：token 全耗在内部推理上，`content` 返回空。

## 词表来源

`words.js` 里的 7,777 个词来自《六级词汇7884词（正序版）》的 docx。

两点必须说明：

1. **原文件的「释义」列整列是空的**（转换时丢失，文档里只剩词头、音标和少量残留中文）。所以内置词表**只有词头和音标，没有释义**。释义在你读文章时自动补进来——AI 写文章时会为每个词给出中文，遇到一次就记一次。
2. **原音标存在字体映射错误**（`θ` 被用来代替 `ə`，`œ` 代替 `æ`）。生成词表时已还原，例如 `abandon` 从 `/θ ˈbœndθθn/` 修正为 `/ə ˈbændən/`。

为了让猜词一开始就能玩，`words.js` 里另外内置了 402 条手写释义（高频核心词），作为释义的兜底来源。

如果你有释义完整的词表，直接在词书页「导入我的词表」导入即可（`word,pos,释义`，一行一个），导入后会跟内置词表合并，一起参与选词和掌握度统计。

## 没有做的

- 间隔复习算法（现在用「勾数」做粗略优先级）
- 多设备同步（数据只在本机）
- 新闻自动抓取（时事内容由 AI 生成，不保证是最新事件）
